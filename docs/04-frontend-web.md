# Этап 4. Фронт: веб-версия

**Оценка:** ≈6–8 ч

**Цель:** викторина полностью проходится в браузере.

## Зависимости

- Этап 1: каркас Nuxt, Pinia, `useApi()`.
- Этап 3: рабочие эндпоинты и DTO в `packages/shared`.

## Задачи

### Store и данные
- [ ] Pinia-store `participant`: `nickname`, синхронизация с `localStorage` (чтение при старте, запись при изменении).
- [ ] Pinia-store `quiz`: вопросы, текущий индекс, ответы `{ questionId, optionId }[]`, результат, `isFirst`.
- [ ] Прогресс прохождения (индекс и ответы) тоже сохранять в `localStorage`, чтобы перезагрузка посреди викторины не сбрасывала ответы. По желанию.
- [ ] Типы ответов API импортировать из `@memequiz/shared`.

### Экран ника (`/`)
- [ ] Поле ввода с теми же правилами, что на бэкенде (zod-схема из `shared`).
- [ ] Ошибка валидации показывается под полем, кнопка «Начать» неактивна при невалидном нике.
- [ ] Ник предзаполняется из `localStorage`.
- [ ] По «Начать» сохранить ник в store и вызвать `/api/me/status`.

### Проверка статуса
- [ ] Если `completed: true`, сохранить результат в store и сразу перейти на `/result`.
- [ ] Если `completed: false`, загрузить `/api/quiz` и перейти на `/quiz`.
- [ ] Route middleware: на `/quiz` и `/result` без ника редиректить на `/`.

### Экран вопроса (`/quiz`)
- [ ] Картинка мема (с фиксированным соотношением сторон, чтобы не прыгала вёрстка), текст вопроса, варианты ответа кнопками.
- [ ] Прогресс «3/12» и прогресс-бар (сквозной по всей викторине) плюс название текущего раунда.
- [ ] Перед первым вопросом каждого раунда заставка: `title`, `description`, кнопка «Начать раунд».
- [ ] Выбор варианта подсвечивается, кнопка «Далее» активна только после выбора.
- [ ] На последнем вопросе кнопка «Завершить».
- [ ] Предзагрузка картинки следующего вопроса (`new Image().src`).
- [ ] Индикатор загрузки картинки, если её ещё нет.

### Отправка
- [ ] Все ответы отправляются одним запросом `POST /api/quiz/submit` в конце.
- [ ] Состояние загрузки: кнопка заблокирована, показан спиннер.
- [ ] Защита от двойного клика: флаг `submitting` в store, повторный вызов игнорируется.
- [ ] Ошибка сети или сервера: сообщение и кнопка «Повторить», ответы не теряются.
- [ ] После успеха очистить прогресс прохождения и перейти на `/result`.

### Экран результата (`/result`)
- [ ] Баллы «X из Y».
- [ ] Сообщение в зависимости от доли правильных ответов, например:
  - 0–30%: «новичок в мемах»;
  - 30–70%: «уверенный пользователь»;
  - 70–90%: «ты мемолог 80 уровня»;
  - 90–100%: «легенда мемов».
- [ ] Если `isFirst: false`, показать «засчитан твой первый результат: X».
- [ ] Ссылка на лидерборд.

### Лидерборд (`/leaderboard`)
- [ ] Таблица: место, ник, баллы, дата (локальный формат, `Intl.DateTimeFormat`).
- [ ] Подсветка строки текущего пользователя (сравнение по нормализованному нику).
- [ ] Состояния загрузки, пустого списка и ошибки.

### Адаптив
- [ ] Mobile-first, проверить ширины 360, 390 и 430 px.
- [ ] Кнопки не меньше 44 px по высоте, крупный шрифт вариантов.
- [ ] Учесть `env(safe-area-inset-*)` уже сейчас (пригодится в Telegram).
- [ ] Цвета через CSS-переменные, чтобы на этапе 7 подменить их на `themeParams` Telegram.
- [ ] Нет горизонтального скролла.

## Готово, когда

- [ ] Человек проходит викторину с телефона от начала до конца.
- [ ] Перезагрузка страницы не теряет ник.
- [ ] Повторный вход с тем же ником сразу ведёт на результат.
- [ ] Двойной клик по «Завершить» не создаёт двух запросов.

## Артефакты

- `apps/web/app/pages/{index,quiz,result,leaderboard}.vue`
- `apps/web/app/stores/{participant,quiz}.ts`
- `apps/web/app/middleware/` (проверка ника)

## Риски / заметки

- `localStorage` может быть недоступен (приватный режим, некоторые WebView). Оборачивайте обращения в try/catch.
- Не храните правильные ответы на фронте: их и нет в API, но не добавляйте их «для удобства».
- Не завязывайтесь на hover: в Telegram и на телефонах его нет.
