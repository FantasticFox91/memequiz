# Этап 4. Фронт: веб-версия

**Оценка:** ≈6–8 ч

**Цель:** викторина полностью проходится в браузере.

## Зависимости

- Этап 1: каркас Nuxt, Pinia, `useApi()`.
- Этап 3: рабочие эндпоинты и DTO в `packages/shared`.

## Задачи

### Store и данные
- [x] Pinia-store `participant`: `nickname`, синхронизация с `localStorage` (чтение при старте, запись при изменении).
- [x] Pinia-store `quiz`: вопросы, текущий индекс, ответы `{ questionId, optionId }[]`, результат, `isFirst`.
- [x] Прогресс прохождения (индекс и ответы) тоже сохранять в `localStorage`, чтобы перезагрузка посреди викторины не сбрасывала ответы. По желанию.
- [x] Типы ответов API импортировать из `@memequiz/shared`.

### Экран ника (`/`)
- [x] Поле ввода с теми же правилами, что на бэкенде (zod-схема из `shared`).
- [x] Ошибка валидации показывается под полем, кнопка «Начать» неактивна при невалидном нике.
- [x] Ник предзаполняется из `localStorage`.
- [x] По «Начать» сохранить ник в store и вызвать `/api/me/status`.

### Проверка статуса
- [x] Если `completed: true`, сохранить результат в store и сразу перейти на `/result`.
- [x] Если `completed: false`, загрузить `/api/quiz` и перейти на `/quiz`.
- [x] Route middleware: на `/quiz` и `/result` без ника редиректить на `/`.

### Экран вопроса (`/quiz`)
- [x] Картинка мема (с фиксированным соотношением сторон, чтобы не прыгала вёрстка), текст вопроса, варианты ответа кнопками.
- [x] Прогресс «3/12» и прогресс-бар (сквозной по всей викторине) плюс название текущего раунда.
- [x] Перед первым вопросом каждого раунда заставка: `title`, `description`, кнопка «Начать раунд».
- [x] Выбор варианта подсвечивается, кнопка «Далее» активна только после выбора.
- [x] На последнем вопросе кнопка «Завершить».
- [x] Предзагрузка картинки следующего вопроса (`new Image().src`).
- [x] Индикатор загрузки картинки, если её ещё нет.

### Отправка
- [x] Все ответы отправляются одним запросом `POST /api/quiz/submit` в конце.
- [x] Состояние загрузки: кнопка заблокирована, показан спиннер.
- [x] Защита от двойного клика: флаг `submitting` в store, повторный вызов игнорируется.
- [x] Ошибка сети или сервера: сообщение и кнопка «Повторить», ответы не теряются.
- [x] После успеха очистить прогресс прохождения и перейти на `/result`.

### Экран результата (`/result`)
- [x] Баллы «X из Y».
- [x] Сообщение в зависимости от доли правильных ответов, например:
  - 0–30%: «новичок в мемах»;
  - 30–70%: «уверенный пользователь»;
  - 70–90%: «ты мемолог 80 уровня»;
  - 90–100%: «легенда мемов».
- [x] Если `isFirst: false`, показать «засчитан твой первый результат: X».
- [x] Ссылка на лидерборд.

### Лидерборд (`/leaderboard`)
- [x] Таблица: место, ник, баллы, дата (локальный формат, `Intl.DateTimeFormat`).
- [x] Подсветка строки текущего пользователя (сравнение по нормализованному нику).
- [x] Состояния загрузки, пустого списка и ошибки.

### Адаптив
- [ ] Mobile-first, проверить ширины 360, 390 и 430 px.
- [x] Кнопки не меньше 44 px по высоте, крупный шрифт вариантов.
- [x] Учесть `env(safe-area-inset-*)` уже сейчас (пригодится в Telegram).
- [x] Цвета через CSS-переменные, чтобы на этапе 7 подменить их на `themeParams` Telegram.
- [x] Нет горизонтального скролла.

## Готово, когда

- [ ] Человек проходит викторину с телефона от начала до конца.
- [ ] Перезагрузка страницы не теряет ник.
- [ ] Повторный вход с тем же ником сразу ведёт на результат.
- [ ] Двойной клик по «Завершить» не создаёт двух запросов.

## Артефакты

- `apps/web/app/pages/{index,quiz,result,leaderboard}.vue`
- `apps/web/app/stores/{participant,quiz}.ts`
- `apps/web/app/middleware/` (проверка ника)

## Риски / заметки

- `localStorage` может быть недоступен (приватный режим, некоторые WebView). Оборачивайте обращения в try/catch.
- Не храните правильные ответы на фронте: их и нет в API, но не добавляйте их «для удобства».
- Не завязывайтесь на hover: в Telegram и на телефонах его нет.
