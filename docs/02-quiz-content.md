# Этап 2. Контент викторины

**Оценка:** ≈2–4 ч (зависит от количества мемов)

**Цель:** вопросы описаны в понятном формате и доступны бэкенду.

## Зависимости

- Этап 1: есть `packages/shared` и `apps/api`.

## Задачи

### Формат вопроса
- [x] Описать zod-схему вопроса в `packages/shared`:
  - `id`: строка, стабильная, например `q01`;
  - `type` (опционально): `guess-meme`, `continue-phrase` и т.п.;
  - `image`: путь к картинке относительно статики, например `/memes/q01.webp`;
  - `audio` (опционально): фрагмент песни `/audio/s01.mp3` или `.m4a`; нужен `image`, `audio` или оба;
  - `text`: текст вопроса;
  - `options`: массив `{ id, text }`, 2–4 варианта;
  - `imageAlt`: описание картинки для доступности;
  - `correctId`: id правильного варианта.
- [x] Раунды: файл описывает массив раундов `{ id, title, description?, questions }`, вопросы идут внутри раунда. `id` вопросов уникальны по всей викторине, баллы считаются за каждый вопрос, `total` равен общему числу вопросов. Публичная схема `PublicRound`.
- [x] Описать отдельную публичную схему или тип `PublicQuestion` без `correctId`.
- [x] Вывести TypeScript-типы из zod-схем (`z.infer`).

### Хранение

- [x] Проверки при загрузке: уникальность `id` вопросов, уникальность `id` вариантов внутри вопроса, `correctId` есть среди `options`, файл картинки существует.

## Викторины

Каждая викторина — отдельный файл `apps/api/content/quizzes/<id>.json`, `id` = имя файла (по нему хранятся результаты, после запуска не менять). У каждой своя засчитанная первая попытка и свой лидерборд, ник участника общий.

```json
{
  "title": "Музыка",
  "emoji": "🎵",
  "description": "Угадай песню по фрагменту",
  "order": 2,
  "draft": true,
  "rounds": [ ... ]
}
```

- `order` — порядок кнопок на главной.
- `draft: true` — черновик: на проде кнопка «Скоро» и api отдаёт 404, локально играется; отсутствующие картинки и песни у черновика дают только warning. Когда вопросы готовы — убрать `draft`.
- `"pick": 15` у раунда — каждый участник получает 15 случайных вопросов раунда (а не все). Набор зависит от участника и не меняется при перезагрузке и повторной попытке, сервер проверяет ответы по нему же. Если добавить или убрать вопрос раунда, наборы у всех перетасуются: у тех, кто сейчас проходит, отправка не пройдёт (400), меняйте вопросы до запуска.
- Новая викторина — новый файл, код менять не нужно. Звания на экране результата задаются в `apps/web/app/pages/result/[id].vue` (`VERDICTS`), для неизвестного id — общие.

## Как добавить мем

1. Положить исходник в `content/memes-src/` (в git не попадает), имя файла = id вопроса: `q01.jpg`.
2. `pnpm content:optimize`: ресайз до 800 px, webp до 200 КБ, сводка по весу.
3. Добавить вопрос в нужный раунд (`questions` раунда) в `apps/api/content/quizzes/memes.json`.
4. Перезапустить api: при ошибке в файле или отсутствии картинки он не стартует и пишет, что не так.

## Как добавить песню («угадай песню»)

1. Вырезать фрагмент 10–20 секунд и сжать, например `ffmpeg -ss 0:45 -t 15 -i song.mp3 -ac 1 -b:a 96k -af afade=t=out:st=14:d=1 apps/web/public/audio/s01.mp3`. Ориентир до ~300 КБ на файл.
2. Имя файла нейтральное (`s01.mp3`, не `rickroll.mp3`): путь виден в сети и подсказывает ответ.
3. Добавить вопрос с `"type": "guess-song"` и `"audio": "/audio/s01.mp3"`. `image` необязателен: без него будет только плеер, с ним — картинка и плеер под ней.

## Вопрос с вводом ответа

Вместо `options` и `correctId` указать `acceptedAnswers`: участник вводит ответ текстом.

```json
{ "id": "s01", "type": "guess-song", "audio": "/audio/s01.mp3", "text": "Что за песня?",
  "acceptedAnswers": ["Белые розы", "Ласковый май — Белые розы"] }
```

- Сравнение без учёта регистра, ё/е, пунктуации; опечатки: до 4 символов — ни одной, 5–9 — одна, длиннее — две.
- Ответы засчитанной попытки сохраняются в `text_answers`. Проверка вручную на `/admin` (логин и пароль — `ADMIN_USERNAME` / `ADMIN_PASSWORD` в `.env`, сессия 7 дней): вкладка «По вопросам» собирает одинаковые ответы в одну строку и оценивает их пачкой; вкладка «По участникам» показывает все ответы одного участника (поиск по нику) и оценивает каждый отдельно.
- Если вручную засчитали частый вариант, добавьте его в `acceptedAnswers`, чтобы дальше он засчитывался сам.

В Docker-образе api нет статики фронта, поэтому проверка картинок там пропускается (warning в логе). Проверяйте локально.

## Риски / заметки

- Картинки из `public/` не получают хэш в имени. При замене картинки меняйте имя файла (`q01-v2.webp`), иначе пользователи увидят закэшированную старую.
- Мемы могут быть под авторским правом. Для приватной викторины среди друзей это обычно не проблема, для публичной стоит задуматься.
- `id` вопросов не меняйте после запуска: по ним считаются баллы.
