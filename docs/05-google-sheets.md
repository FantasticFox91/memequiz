# Этап 5. Интеграция с Google Sheets

> **Отменён (2026-10-07).** Результаты и так хранятся в Postgres и видны в лидерборде, а сохранность обеспечивают ежедневные бэкапы (`scripts/backup.sh`). Переменные `SHEETS_ENABLED`/`GOOGLE_*` удалены из env; колонка `synced_at` осталась в схеме, но не используется. План ниже сохранён на случай, если выгрузка всё же понадобится.

**Оценка:** ≈3–4 ч

**Цель:** каждый засчитанный результат появляется в таблице.

## Зависимости

- Этап 0: JSON-ключ service account и таблица с доступом «Редактор».
- Этап 3: `submit` с флагом `isFirst`, колонка `synced_at` в `results`.

## Задачи

### SheetsModule
- [ ] Установить `googleapis` (или облегчённые `@googleapis/sheets` + `google-auth-library`).
- [ ] `SheetsModule` и `SheetsService`: авторизация через `GoogleAuth` с `keyFile` и scope `https://www.googleapis.com/auth/spreadsheets`.
- [ ] Env: `GOOGLE_SHEET_ID`, `GOOGLE_CREDENTIALS_PATH`, `SHEETS_ENABLED` (выключатель для dev). Добавить в zod-схему env и `.env.example`.
- [ ] Ключ подключается в контейнер через Docker secret (`/run/secrets/google-sa.json`) или read-only volume. В образ ключ не попадает.
- [ ] При `SHEETS_ENABLED=false` сервис ничего не делает (no-op), а приложение не требует ключа.

### Структура таблицы
- [ ] Лист `Results` с заголовками в первой строке: ник, источник, id, баллы, из скольких, дата.
- [ ] Закрепить первую строку.
- [ ] Формат колонки «дата»: «Дата и время».
- [ ] Локаль таблицы: Россия, часовой пояс таблицы: Москва.

### Запись
- [ ] `values.append` в диапазон `Results!A:F`, `valueInputOption: USER_ENTERED`, `insertDataOption: INSERT_ROWS`.
- [ ] Вызывать только при `isFirst = true`.
- [ ] Асинхронно: после ответа пользователю (без `await` в обработчике запроса, через событие `@nestjs/event-emitter` или очередь в памяти). Ошибки логируются, а не пробрасываются.
- [ ] После успешной записи `UPDATE results SET synced_at = now() WHERE id = ...`.

### Надёжность
- [ ] Ретраи с экспоненциальным backoff (например 3 попытки: 1 с, 4 с, 16 с) на 429 и 5xx.
- [ ] `@nestjs/schedule`: cron раз в 5 минут выбирает строки с `synced_at IS NULL` (порциями, по `created_at`) и дозаписывает их.
- [ ] Защита от параллельного запуска cron и асинхронной записи одной строки: флаг «в процессе» в памяти или `SELECT ... FOR UPDATE SKIP LOCKED`.
- [ ] Батч-запись: несколько строк одним `append`.
- [ ] Учесть, что `append` может пройти успешно, а `synced_at` не обновиться (падение между шагами). Тогда возможен дубль строки. Для таблицы-копии это допустимо, но лучше в описании листа указать, что дубли возможны.

### Формат даты
- [ ] Перевод `created_at` в часовой пояс `Europe/Moscow` (`Intl.DateTimeFormat` с `timeZone` или `date-fns-tz`).
- [ ] Формат `yyyy-MM-dd HH:mm:ss`. С `USER_ENTERED` Google распознаёт его как дату, и сортировка по колонке работает.
- [ ] Проверить, что значение в ячейке выравнивается вправо (это признак даты, а не текста).

## Готово, когда

- [ ] Новый первый результат появляется в таблице в течение нескольких секунд.
- [ ] Повторная попытка того же участника строку в таблицу не добавляет.
- [ ] При временно отключённом Google API (неверный ID таблицы или выключенная сеть) результат сохраняется в БД, а после восстановления cron его дописывает.
- [ ] Сортировка по колонке «дата» работает как по дате.

## Артефакты

- `apps/api/src/sheets/sheets.module.ts`, `sheets.service.ts`, `sheets-sync.cron.ts`
- Переменные `GOOGLE_SHEET_ID`, `GOOGLE_CREDENTIALS_PATH`, `SHEETS_ENABLED`
- Docker secret или volume с ключом в `docker-compose.yml`

## Риски / заметки

- Квоты Sheets API: примерно 60 запросов на запись в минуту на пользователя (service account). При наплыве участников спасают батчи из cron.
- Ник может начинаться с `=`, `+`, `-` или `@`. С `USER_ENTERED` Google воспримет его как формулу. Экранируйте ник (префикс `'`) или запишите эту колонку отдельным запросом с `RAW`.
- Не логируйте содержимое JSON-ключа при ошибках авторизации.
