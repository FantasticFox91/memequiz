# Этап 8. Полировка и защита

**Оценка:** ≈3–5 ч

**Цель:** приложение устойчиво к злоупотреблениям, проверено вручную и приятно в использовании.

## Зависимости

- Этапы 0–6 обязательны.
- Этап 7 нужен для Telegram-специфичных пунктов (шаринг, HapticFeedback).

## Задачи

### Rate limiting
- [x] `@nestjs/throttler`, глобальный `ThrottlerGuard` (после `TelegramAuthGuard`). Два лимита (`common/throttling.ts`): по участнику (tg id / кука / IP) 60 в минуту и по IP 300 в минуту. `/api/health` без лимита.
- [x] Строгие лимиты через `@Throttle()`: `POST /api/quiz/submit` 5 в минуту на участника (100 в час на IP), `GET /api/me/status` 30 на участника (120 на IP). Лимит по участнику, а не по IP, чтобы компания на одном Wi-Fi не мешала друг другу.
- [x] За Caddy использовать реальный IP клиента: `app.set('trust proxy', ...)` в Nest, а в Caddy передавать `X-Forwarded-For` (делается по умолчанию).
- [x] Ответ 429 обрабатывается на фронте понятным сообщением (`utils/api-error.ts`).

### Анти-абуз для веба
- [x] Ограничение новых web-участников с одного IP: `submit` не больше 100 в час с IP (`SUBMIT_LIMITS.ip`), независимо от кук. Компании на одном Wi-Fi хватает, массово накрутить лидерборд нельзя.
- [x] Фильтр неприличных ников (`participant/nickname-filter.ts`): корень где угодно в нике, без учёта регистра, пробелов, `_`, `-` и повторов букв, с заменой похожих символов (латиница↔кириллица, `0→о`, `1→и`, `3→з`, `@→а`). Сайт: 400 «Такой ник не подойдёт» уже на «Начать». Telegram: ник из профиля не отклоняется, а заменяется на `tg<id>`.
- [x] Список стоп-слов: `apps/api/content/nickname-stopwords.txt` (строки с `!` — исключения вроде «корабля»). После правки перезапустить api.
- [x] Ручное удаление записи из лидерборда: `scripts/delete-result.sh` на сервере (`--list`, по нику как в лидерборде или `--id N`; показывает запись и спрашивает подтверждение, заодно удаляет отметку старта).

### Ручной чек-лист перед релизом (автотесты не пишем)
- [ ] Прохождение: ввод ника → все вопросы → результат с баллами.
- [ ] Повторная попытка: тот же ник → сразу экран результата с первым результатом.
- [ ] Лидерборд: участник в списке, его строка подсвечена.
- [ ] Всё то же на телефоне (iOS и Android) и в Telegram.

### Шаринг
- [x] Кнопка «Поделиться результатом» на экране результата (`useShareResult`). Делимся засчитанным результатом. В Telegram это MainButton.
- [x] Веб: Web Share API (`navigator.share`), иначе копирование текста со ссылкой в буфер (кнопка показывает «Скопировано»).
- [x] Telegram: `openTelegramLink("https://t.me/share/url?...")` со ссылкой на Mini App `t.me/<bot>?startapp`. Username бота фронт берёт из `GET /api/bot` (бот узнаёт его при старте), без бота — ссылка на сайт.
- [x] Текст: «Мой результат в MemeQuiz: X из Y за M:SS — «вердикт» 🧠 Сможешь лучше?» плюс ссылка.

### Мелочи UX
- [x] Анимации: смена страниц и вопросов (`<Transition>`), лесенка вариантов и строк лидерборда, отклик на выбор, прогресс-бар через `scaleX`, баллы «набегают», конфетти из эмодзи за 70%+, покачивание поля при ошибке. Только `transform`/`opacity`; при `prefers-reduced-motion` остаются только появления по прозрачности.
- [x] Вибрации (`useHaptics`): выбор варианта, «Далее», старт раунда, ошибка, результат (success от 50%, иначе warning). В Telegram — `HapticFeedback`, в браузере — `navigator.vibrate` (Android).
- [x] Экран ошибки (`components/ErrorState.vue`) с кнопкой «Повторить» на викторине, результате и лидерборде. Без сети — отдельный текст и автоповтор по событию `online`.
- [x] Страница 404 и общая страница ошибок (`app/error.vue`), в Telegram «На главную» на MainButton.
- [x] Favicon (SVG + PNG 32 + apple-touch-icon), `<title>`, description и Open Graph-превью 1200×630 с коллажем мемов. Генерация: `pnpm content:brand` (`scripts/make-brand-assets.mjs`). Абсолютные `og:image`/`og:url` из `SITE_ADDRESS` (build arg образа caddy).

### Мониторинг
- [ ] Uptime-проверка `https://<hostname>/api/health` (Uptime Kuma, если он уже есть в хоумлабе) с интервалом 1–5 минут.
- [ ] Уведомления о падении в Telegram (у Uptime Kuma есть встроенная интеграция).
- [ ] Отдельная проверка срока действия TLS-сертификата.
- [ ] Алерт, если свежего дампа нет больше суток: в Uptime Kuma монитор типа Push с интервалом 25 ч, его URL — в `BACKUP_PUSH_URL` в `.env` на сервере; `backup.sh` дёргает его после удачного дампа.

## Готово, когда

- [x] Спам запросами к submit и status упирается в 429.
- [x] Неприличный ник отклоняется с понятной ошибкой.
- [ ] Ручной чек-лист пройден.
- [ ] Результатом можно поделиться из веба и из Telegram.
- [ ] Падение API приходит уведомлением.

## Артефакты

- Настройки `ThrottlerModule`, файл стоп-слов
- Монитор в Uptime Kuma

## Риски / заметки

- Лимиты по IP могут задеть людей за одним NAT (офис, мобильный оператор). Не делайте их слишком жёсткими.
- Фильтр ников никогда не будет идеальным. Возможность ручного удаления важнее сложных эвристик.
- При ручной проверке на prod используйте уникальные тестовые ники и потом удаляйте эти записи.
