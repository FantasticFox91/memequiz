# Этап 8. Полировка и защита

**Оценка:** ≈3–5 ч

**Цель:** приложение устойчиво к злоупотреблениям, проверено вручную и приятно в использовании.

## Зависимости

- Этапы 0–6 обязательны.
- Этап 7 нужен для Telegram-специфичных пунктов (шаринг, HapticFeedback).

## Задачи

### Rate limiting
- [ ] Установить `@nestjs/throttler` и включить глобальный `ThrottlerGuard` с мягким лимитом.
- [ ] Более строгие лимиты через `@Throttle()` на `POST /api/quiz/submit` (например 5 в минуту) и `GET /api/me/status` (например 30 в минуту).
- [ ] За Caddy использовать реальный IP клиента: `app.set('trust proxy', ...)` в Nest, а в Caddy передавать `X-Forwarded-For` (делается по умолчанию).
- [ ] Ответ 429 обрабатывается на фронте понятным сообщением.

### Анти-абуз для веба
- [ ] Ограничение количества новых web-участников с одного IP (например не больше N submit с разными никами в час). Хранение счётчиков в памяти или в отдельной таблице.
- [ ] Фильтр неприличных ников: список стоп-слов (русский и английский) с учётом замен символов (`0→о`, `@→а`, латиница вместо кириллицы).
- [ ] Список стоп-слов вынести в файл, чтобы пополнять без изменения кода.
- [ ] Ручное удаление записи из лидерборда (SQL-скрипт или простой защищённый admin-эндпоинт).

### Ручной чек-лист перед релизом (автотесты не пишем)
- [ ] Прохождение: ввод ника → все вопросы → результат с баллами.
- [ ] Повторная попытка: тот же ник → сразу экран результата с первым результатом.
- [ ] Лидерборд: участник в списке, его строка подсвечена.
- [ ] Всё то же на телефоне (iOS и Android) и в Telegram.

### Шаринг
- [ ] Кнопка «Поделиться результатом» на экране результата.
- [ ] Веб: Web Share API (`navigator.share`), иначе копирование текста со ссылкой в буфер.
- [ ] Telegram: `switchInlineQuery` (нужен inline-режим бота, `/setinline` в BotFather) или `openTelegramLink('https://t.me/share/url?url=...&text=...')` со ссылкой на бота или Mini App.
- [ ] Текст: «Я набрал X из Y в MemeQuiz, а ты?» плюс ссылка.

### Мелочи UX
- [ ] Анимации переходов между вопросами (`<Transition>`, `prefers-reduced-motion` учитывается).
- [ ] В Telegram: `HapticFeedback.selectionChanged()` при выборе варианта, `notificationOccurred('success')` на результате.
- [ ] Экран-заглушка при ошибке сети или недоступном API с кнопкой «Повторить».
- [ ] Страница 404 для несуществующих роутов.
- [ ] Favicon, `<title>` и Open Graph-превью для ссылки в мессенджерах.

### Мониторинг
- [ ] Uptime-проверка `https://<hostname>/api/health` (Uptime Kuma, если он уже есть в хоумлабе) с интервалом 1–5 минут.
- [ ] Уведомления о падении в Telegram (у Uptime Kuma есть встроенная интеграция).
- [ ] Отдельная проверка срока действия TLS-сертификата.
- [ ] По желанию: алерт, если есть несинхронизированные с Sheets строки старше часа (отдельный health-подэндпоинт).

## Готово, когда

- [ ] Спам запросами к submit и status упирается в 429.
- [ ] Неприличный ник отклоняется с понятной ошибкой.
- [ ] Ручной чек-лист пройден.
- [ ] Результатом можно поделиться из веба и из Telegram.
- [ ] Падение API приходит уведомлением.

## Артефакты

- Настройки `ThrottlerModule`, файл стоп-слов
- Монитор в Uptime Kuma

## Риски / заметки

- Лимиты по IP могут задеть людей за одним NAT (офис, мобильный оператор). Не делайте их слишком жёсткими.
- Фильтр ников никогда не будет идеальным. Возможность ручного удаления важнее сложных эвристик.
- При ручной проверке на prod используйте уникальные тестовые ники и потом удаляйте эти записи.
